# Наскрізний проєкт: конкурентна операція

Ця тека продовжує проєкт із OBDZ-LAB02. Скопіюйте сюди з LAB02 усе, що стосується бази: `migrations/`, `data/`, `make_data.py`, `load.psql`, `post_load.sql` (і за бажанням `integrity_checks.sql`, `er_model.json`, `schema.sql`, `data_dictionary.md`). Потім додайте теку `concurrency/`:

- `operation.py`: функція `perform(conn, worker, i)`, що виконує одну операцію вашого проєкту, яка конкурує за дані, і за потреби `prepare(conn)`, що готує змагання за обмежений ресурс;
- `invariant.sql`: запит, що повертає рядки, які порушують інваріант (порожній результат означає, що все гаразд);
- `concurrency.json`: назва прийому захисту й таблиці, яких він стосується;
- `NOTES.md`: три короткі розділи «Інваріант», «Захист», «Що було б без захисту».

Розгорнути проєкт у схемі `project` вашої бази: `python project_check/deploy_project.py`.
Перевірити: `pytest project_check` (потрібен запущений PostgreSQL). Кожну зміну міграцій і кожну версію операції фіксуйте окремим комітом.
